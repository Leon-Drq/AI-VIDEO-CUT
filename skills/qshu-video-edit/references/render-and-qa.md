# 渲染与检查

基础层级：干净对白/底图 → B-roll/图解 → 真人画中画 → 标签与来源 → 最后字幕。有前景粒子与实物叠层时按 [image-led-motion.md](image-led-motion.md) 分配层级和保护区域，粒子不覆盖人物小窗、金额单位或字幕。

真人背后主标题单独采用“背景 → 粗白标题 → 连续 alpha 恢复原人物 → 最后字幕”的层级，详见 [visual-system.md](visual-system.md)。人物遮罩须与最终帧映射、裁切、缩放一致；不能直接把标题叠在完整人物上，也不能将单帧抠像沿用整段。

复用旧工程时只提炼函数和参数结构，重建路径、时间轴、对象名称和素材列表；不要复制旧人脸、音轨、照片到新项目。

## 实现注意

- 发现本机 Python、FFmpeg/FFprobe、字体与可用编码器，不写死用户目录。脚本显式接受可执行文件路径。
- Windows 中文路径的文本显式 UTF-8；调用系统校验脚本可设 `PYTHONUTF8=1`。FFmpeg 使用参数列表；ASS 滤镜从项目 cwd 引用相对路径可避免盘符冒号转义。
- rawvideo 管道明确尺寸、像素格式、帧率、帧数。只消费 N 帧时解码器也限制 N 帧，避免提前关闭造成 broken pipe；检查编码器和实际输出帧数。
- 人脸检测若不兼容中文模型路径，API 支持时传模型字节。依赖缺失时使用可用实现，不默认安装整套模型环境。
- 通用交付 H.264/yuv420p、AAC或兼容原轨、MP4 faststart；音轨复制不可用时才重编码并记录。
- 新片默认原速；视觉修改保留已确认速度与时间轴。只要求口播加速时分别映射真人、声音、字幕和配图语义，保留案例内部已确认的动作速度，不能对最终合成整体再加速。
- 案例源裁切、展示框和动画分别设置；整体按 `contain` 等比包含，禁止靠宽高独立缩放填满窄条。完整取景及源视频退场检查见 [full-frame-materials.md](full-frame-materials.md)。
- 中英是两路字幕逻辑轨，允许跨语言同时显示。检查各轨内部重叠、实际字宽与布局，不使用单语“一行/固定字符数”检测器误报双语。

## 最终检查

1. 完整解码最终 MP4，不只检查退出码或文件存在。
2. 核对视频/音频流、尺寸、帧率、实际帧数、总时长与起始时间。对白剪辑后检查同步。
3. 扫描黑屏、低运动、异常静音候选，逐一判断，不把阅读停留一概当故障。
4. 测量响度和 true peak，确认无削波、突变。原音轨复制可比较解码 PCM 哈希；一致证明未改变音轨，不证明已经人工试听或内容正确。
5. 检查每行字幕真实宽度、边界、阅读时长、数字专名、中英分区和最终烧录效果。
6. 从最终 MP4 提取首尾、约每 2–3 秒及每个设计转场前/中/后画面，异常再加密。查看人脸、嘴部、手势、素材主体、文字和署名。
   实物动效额外检查最密集阶段、旧标签退出、浅色物体上的单位对比和手机尺寸辨识度；静帧无法验证运动是否自然，要播放相应动作片段，记录实际查看方式。
7. 低运动提示结合帧差、人像区域帧差与画面解释。帧差大于零不是所有卡顿问题的通用证明。
8. 按 [hook-and-polish.md](hook-and-polish.md) 专项复核开头 0–3 秒、画面网址、案例局部清晰度与叠层。最终 MP4 中每个网页/录屏素材的入场、运动极值、退场及收尾都要检查；OCR 或渲染文本搜索只作辅助。记录明暗场景选择、避让修正及实际检查范围。
9. 真人主标题确认白色、粗重无衬线、无底框，检查入出点和人物动作极值。播放自然遮挡片段，核对发丝/帽沿边缘、手势穿字、脸上漏字、轮廓闪烁与关键词可读性；记录实际发生重叠的区间。因构图或抠像改用无重叠排字时如实记录，不称为已实现人后遮挡。
10. 检查所有案例是否完整且足够大：标题、轴、单位、海报边缘、产品主体和关键按钮均无意外截断；源素材自带缩放、拖移、模板退场也要取到动作边界。说明用静帧应有来源时间与理由，不能冒充动态功能演示。
11. 自制强调为姜黄，暖白上使用足够深的版本；不改真实品牌与图表色。真人背景未新增模糊、马赛克或生成替换。视频全程原本已经失焦的部分不能声称被恢复。

写 `verify/delivery-review.md`，记录实际检查、未执行部分及已解释提示。有实质问题先修复再交付；不把音轨哈希校验称作人工听感评审。

画面局部修订时：用新版本名导出；时间轴未改则复用原音轨与字幕时码。若裁切小窗有问题，检查所有小窗段和动作极值，不能只修用户截图对应的一帧。QA 报告补充完整头部、手机辨识度、图文避让和改动范围检查。
