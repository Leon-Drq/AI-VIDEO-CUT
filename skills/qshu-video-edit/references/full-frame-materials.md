# 完整取景与大画面

处理“案例只有一半、画面太窄、运动时标题消失”的问题。将来源取景、展示容器和动画时域分别检查；仅把容器加宽，修不好已在来源层裁掉的文字。

## 三个独立坐标空间

1. **源片坐标**：探测真实宽高与旋转，记录来源入出点。需要去地址栏时先判断可见内容的完整边界。录屏中的网页可能在移动，固定裁切框不能只按某一帧确定。
2. **内容框**：选择需要保留的完整对象，包含标题、轴、单位、品牌、关键按钮及必要上下文。按内容边缘留少量余量，不把阴影或圆角当成有效内容范围。
3. **成片展示框**：根据真人、标题、字幕与平台控件决定可用空间。先决定主次和区域，再等比缩放。圆角会额外削掉四角，关键字不能贴着圆角边缘。

完整内容宽高为 `sw, sh`，目标可用框为 `x, y, bw, bh` 时：

```text
scale = min(bw / sw, bh / sh)
dw = sw * scale
dh = sh * scale
dx = x + (bw - dw) / 2
dy = y + (bh - dh) / 2
```

这是整体案例的默认等比包含方式。不要用取最大缩放比的 `cover` / `ImageOps.fit` 将完整海报塞进固定窄条，也不要分别拉宽、压扁。需要裁切式细节特写时单独建镜头，说明其意义，并先给足完整上下文。

## 大幅展示的排版起点

对 1080×1920 竖屏，主案例可从约 1000–1024 px 宽试排；保持实际比例，16:9 案例因此约 563–576 px 高，不应硬压成 300 px 的长条。其他比例按实际计算，不套固定高度。主画面可以宽，标题、轴标签、按钮、字幕等关键内容仍要避开目标平台 UI。

- 页面图文太多：先展示整页建立上下文，再按口播放大真实细节。不要把整页缩到无法阅读，也不要一开始就裁没标题和主体。
- 横版教学：保留横版中央展示，公式和图形完整。上下空间用克制的说明或自然留白组织；不强制填满，更不以模糊原片复制层填充。
- 案例与真人同屏：先保护脸、嘴及关键手势，再扩大案例区；可调整真人构图或短时采用较大画中画。不能只为了保留原模板槽位而牺牲案例比例。
- 图像像素不足：找高清源、换清晰时刻或缩小无用外壳。锐化不能补回缺失的细节。

## 动态来源：不要只修一帧

原演示的缩放和模板退场也会让内容越界；检查所有使用区间的来源帧和最终帧，尤其最大缩放、拖拽、场景切换以及首尾。固定裁切框只在其覆盖所有必要内容时使用。

处理顺序按语义选择：

1. 换同一来源中更完整、质量更高的镜头或更合适的入出点。
2. 改为完整源画面等比展示，或跟踪内容范围；边缘和字保持稳定，避免修复产生抖动。
3. 如任务是解释图表、页面、设计稿，可以采用清晰完整的关键帧并给适当阅读停留，来源清单记录时间点及冻结用途。用轻微运镜也必须保持边缘完整，不把自制运镜说成产品能力。
4. 如任务是在证明交互或动画效果，必须保留真实动态片段或换真实演示，不能用静帧代替过程。

若来源最后一秒进入模板空白、物件飞走或不相关下镜头，应将来源出点截在有效内容结束处；阅读需要更久时在真实有效帧上停留。不要硬循环、把空白尾帧补入成片，或不断冻结来掩盖整段素材不适用。

## 回归样例与检查方式

| 曾出现的问题 | 应保留的内容 | 修复验收 |
| --- | --- | --- |
| 数据图表挤成横条 | 图表标题、完整柱线、两轴刻度及单位 | 大幅等比展示；放大状态仍不切顶部与底部 |
| 办公幻灯片顶部被裁 | 完整标题、图表、结论与必要页边距 | 按实际页面边缘取景，来源缩放时检查范围是否变化 |
| 巧克力海报左侧文字只剩半行 | 品牌、整行标题、完整产品组合 | 换完整稳定源帧或镜头，先整稿后细节 |
| 鞋产品预览后半段变空白 | 完整产品与有效案例 | 检查预览末尾；调整来源出点或有限停留，不能仅检查首帧 |
| 人像小窗放大仍掉发顶 | 完整头部与上肩 | 重新取源范围，再调整窗口大小，见 [人像取景](portrait-framing.md) |

这些描述是故障类型，不是固定素材或裁切坐标。新片重新取景。

先看输出原尺寸，再看约 360 px 宽的手机预览。每个案例检查入场、停稳、运动极值、最密集状态、退场前与下一镜头；异常点前后按帧加密。动态镜头还要播放，避免联系表漏掉短暂空白或截断。来源文字搜索只能辅助，最终编码画面才是验收对象。

修订报告写清哪些镜头改为完整动态、哪些采用了说明用静帧；不能把所有静帧都判成故障，也不能用画中画还在动证明主案例没有卡顿。一般 QA 见 [渲染与检查](render-and-qa.md)。
