# Q叔口播视频剪辑

由冷科长式 B-roll 方法与用户逐次确认的剪辑偏好整理而成。让真人负责表达，让真实案例解释台词；先保证对象完整、手机上看得清，再用分层与动效增加吸引力。本目录可独立安装，不要求先安装 `lengke-broll`，也不包含每期原片、成片或模型。

## 默认制作标准

以下是本用户的默认偏好；当前请求、已确认项目设置优先。

| 项目 | 默认做法 |
| --- | --- |
| 画幅 | 新建抖音口播按 9:16、1080×1920 组织；已有工程沿用已确认尺寸。横版素材在竖版中央保持原比例，不强裁成竖屏、不拉伸 |
| 速度 | 新片原速 1.0×，不继承旧片的 1.2×。同一片的视觉修改保留已确认速度、剪口与字幕时码 |
| 前3秒 | 首帧有可识别案例或结果，同时露出本人；精彩片段为主题服务，给观众看懂的停留，不靠大量快闪 |
| 真人标题 | 白色、粗重无衬线、正常字宽、无背景框；适合时用连续人物遮罩自然挡住部分字形 |
| 案例画面 | 大幅、完整、等比展示；完整标题、坐标轴、单位、产品主体和关键按钮优先。不能把整张案例挤成窄条 |
| 高亮 | 姜黄色，深色/真人上从 `#D3AD55` 试排；暖白上用更深的 `#966A24`。不改素材自己的品牌色 |
| 背景 | 保留真人原始自然背景，不添加虚化、马赛克或背景生成替换；素材展示可用暖白与深色交替 |
| 网址 | 画面不出现网址、地址栏、收尾链接或引流二维码；完整出处写入项目来源清单 |
| 输出 | 自检后交付可直接观看的正式 MP4，保留原片和旧版，不设置额外预览批准步骤 |

“不虚化”指不新增处理，无法凭此恢复源片已经失焦或打码的细节。无网址与自然背景的处理次序见 [前3秒与精修](references/hook-and-polish.md)，不为清网址再次模糊真人背景。

## 1. 读取素材与现有工程

探测流、时长、帧率、旋转、尺寸、音轨；查看首尾、关键台词与人物动作。优先复用现有 EDL、干净底片、字幕、转录、抠像和来源记录，但核对它们与当前源片及时间轴是否一致。

- 原片：先精剪重复、口误及过长停顿，保留论据、限定词、自然语气和关键反应；不用加速代替对白取舍。
- 已有成片：用户只改视觉时保留叙事、时长、音轨、字幕时码，修改指定问题并检查同类镜头。没有必要不重新转写或重编音轨。
- 用户只要求口播 1.2× 时，将真人画面和声音同步处理、重新映射字幕及语义锚点；案例动作仍保持已确认的节奏，不能对整条成片一键加速。原片本身已变速则不得叠加加速。
- 输入带硬字幕时先找干净中间文件；找不到则为原字幕留位，不重烧一套字幕或靠裁脸、裁手去除。

参考片可访问时实际查看并提炼节奏、主体占比、字体、明暗与素材逻辑；没有查看就不能声称复刻其具体镜头。旧项目的裁切坐标、素材名称和时码不能直接套到新片。

使用 [项目初始化脚本](scripts/init_project.py) 建新版本目录；参数、字段和时间轴校验见 [项目格式](references/project-format.md)。项目工具用于组织和检查，不能代替实际剪辑、渲染与视觉判断。

## 2. 建立语义分镜与开头

把最终台词对应到“对象 → 观众要理解的关系 → 真实素材 → 动作与停留”。素材记入分镜：入出点、`spoken_anchor`、`asset_key`、来源、用途和信息状态。

先读 [前3秒与精修](references/hook-and-polish.md)。开头可用后文最精彩的真实案例作预览并写明理由，仍保留完整脸、发顶和嘴；具体数字、排名、收益及结论不能无依据提前揭示。开头不堆无关案例，不把不同产品拼成同一工具的成果。

- 逐句覆盖产品、人物、职业、地点、步骤、数字与比较；配图不匹配时留真人表达，而非用泛科技机器、廉价卡通人物或无关机器人占位。
- 对象按说到的时间出现，通常最多提前 0.10 秒；合理的主题预告记录 `early_entry_reason`。同一素材呼应复用记录 `reuse_reason`。
- 图优先表达名词，字幕保留完整口播，少量标签补单位、身份、限定或关系。图已清楚表达人物时，不再堆同义姓名大字。
- 信息段有多个论点时依次揭示；完整案例需要停留阅读时允许稳定展示，记录 `hold_reason`。不为凑动画状态破坏完整画面。

密度与标题参考 [视觉系统](references/visual-system.md)；需要头像、实物展开、照片群体或纸币动效时读 [真实素材与分层动效](references/image-led-motion.md)。示意效果不能把“股份估值”变成“现金到账”，也不能抹掉“计划、可能、估算”等限定。

## 3. 获取与筛选素材

优先用户素材、产品或作者自己的公开原始演示、可靠原始资料，再用原创说明图解。实际打开素材检查分辨率、相关性和运动过程；官网收录不等于该工具生成，概念演示也不能当已交付结果。

产品演示优先选具有成熟摄影、产品质感或完整界面动效的案例。不要因为来源官方，就选尺寸很小、示意性强、不能支撑台词的简陋图。Logo 首次出现要足够辨认，与正文主体有明确层级。

按 [素材获取](references/source-acquisition.md) 保存本地路径、稳定来源链接、作者、采集日期、实际许可依据及用途。来源事实核对到具体台词；生成画面只作说明，不能作为事实证据。没有可靠素材时改构图或保留真人，不造假界面补齐。

## 4. 完整大画面与人物合成

**制作案例与录屏镜头前必读 [完整取景与大画面](references/full-frame-materials.md)。** 这也是修改“只剩一半、太窄、标题被截断”的直接处理路径。

- 整体案例用等比 `contain`；先去除无关外壳，再让完整对象进入可用空间。完整展示之后才做有目的的细节特写。
- 1080 竖屏主案例可从约 1000–1024 px 宽起排，高度由源比例决定。按内容让出标题和字幕空间；关键说明仍避开平台控件，不把“放大”变成越界裁切。
- 横版教学或演示在中央保持横版；必要时换大幅主体或暂时全屏展示，不裁掉公式、坐标轴或结论来填满竖屏。
- 原素材自带缩放、推移和模板退场，要检查其完整运动范围。优先换完整镜头或调整来源入出点；完整静帧只用于内容说明，不能冒充产品的实际动态演示。

真人标题与人物层按 [视觉系统](references/visual-system.md) 合成：原背景 → 无底框粗白大字 → 连续 alpha 恢复原始人物 → 其他必要提示 → 最后字幕。保持本人脸、帽子、手势和肤色，不以生成形象替换。抠像不稳时减少重叠或改上方/旁侧排字，不退回黑框标题。

画中画使用 [完整头部取景](references/portrait-framing.md)：检查圆形遮罩后的发顶、耳朵、下巴和上肩。取景和窗大小分别调整；不为排标题再次紧裁人脸。

姜黄只用于自制字幕关键词、标签、路径和强调元素，品牌绿、图表色及真实照片按原样保留。暖白与深色按语义变化，真实拍摄背景保持自然；用户要求补光时只做克制的环境明暗调整，保护肤色，不用虚化制造层次。

## 5. 渲染、复核与交付

沿用可用工程与工具，不强制迁移 FFmpeg、Remotion 或 HyperFrames，也不默认安装模型、使用付费服务或上传原声。必要运行时与模型由实际环境提供；本 skill 不包含一键万能剪辑器。

按 [渲染与检查](references/render-and-qa.md) 检查最终编码文件：完整解码、流与时长、音画同步、字幕宽度、异常黑屏/静音候选、响度和实际画面。时间轴未改且兼容时复制原音轨；哈希一致只能证明音轨未改，不能冒充人工试听。

重点验收：

1. 前3秒既有清晰看点，又能看到本人；真人和素材互不遮挡关键区域。
2. 每个案例入场、停稳、最大缩放、最密集叠层与退场都完整；图表轴、海报边缘、标题、单位和按钮没有无意出框。用户指出一个裁切问题时复核全部同类镜头。
3. 约 360 px 宽手机预览能辨认案例和 Logo；字号与位置不能只靠公式判定，素材画面不被压成窄条。
4. 自制高亮为姜黄，标题无黑框，人物遮挡自然，背景未新增虚化/打码，最终视频无可见网址。
5. 检查镜头动作片段；静帧不代表连续动画正常。报告实际检查范围、无法执行的检查和剩余限制，修复实质问题后再交付。

正式 MP4 用新文件名保存，附可用字幕，来源和检查报告留在项目目录。用绝对路径展示成片，简短说明实质改动和速度。剪辑交付不自动授权发布到社交平台；也不自动追加封面、横版或技能推送任务。
