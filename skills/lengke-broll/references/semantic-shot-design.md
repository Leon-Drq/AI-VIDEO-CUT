# 从参考拆解到语义分镜

适用于用户说“还是不像冷科长”“全屏了但仍然粗糙”，或提供案例要求进一步优化。目标是借鉴参考中对象、证据和关系的展开方法；单纯放大图片、增加转场或延长 B-roll 不能代替叙事设计。

## 1. 先看真实参考，再归纳方法

1. 确认实际可访问的参考文件及版本，探测时长、画幅和帧率。先用覆盖全片的接触表建立结构，再选择开头、证据解释、关系变化、真人回归等代表段加密查看。长片可以分段，记录实际查看范围。
2. 连续播放代表动作，观察上一对象如何移位、下一对象何时加入、何时停稳给观众阅读。静帧不能证明转场、弹性或节奏自然；未播放时明确分析只基于抽帧。
3. 对照口播记录“时间范围、说到什么、主体占比、对象变化、保留/退出的元素、停留原因”。不用参考的某一帧直接推断全片模板。
4. 场景检测只提供候选。平移、缩放、叠层入场也会连续触发检测，候选数量及其中位间隔不能直接称为镜头数或剪辑频率。

将观察与推导分开写在项目分析中：例如“参考里先出现完整表格，再移动并突出一行”是观察；“本片可先建立图表，再聚焦口播对应区间”是迁移方案。不要声称看过未读取的视频，也不要把自己新做的一版写成用户已认可的标准。

## 2. 设计连续的信息状态

按“建立对象 → 提取证据 → 展示关系/结果”规划，适合的段落可省略某一步。一个对象有后续用途时保留其视觉身份，通过移动、缩放或退到次要层给新信息让位；不要每句都重新弹入一套标题、图片和小窗。

使用现有 [project-format.md](project-format.md) 的 `spoken_anchor`、`asset_key`、`state_changes` 等字段，不另造不兼容的时间轴。`state_changes.time` 使用最终时间轴的全局秒数；在 `state` 中说明：

- 本次跟随哪个词句，新增什么事实或关系；
- 旧对象保留、移位、弱化还是退出；
- 动作完成后观众需要看清什么，是否有足够阅读时间。

同一镜头内的状态推进不必拆成多个重复素材条目。跨镜头再次调用同一素材时，按现有规范写 `reuse_reason`。同义字幕更新、持续推近、背景粒子和无意义跳动都不算新信息状态。

| 口播任务 | 有意义的推进 | 常见失败 |
| --- | --- | --- |
| 解释市场走势 | 一张完整图建立时间范围 → 突出口播对应区间/数值 → 明确比较口径 | 完整图和同一图的巨大局部同时争夺注意；用装饰跌线代替实际数据 |
| 介绍文件或法案 | 人物/机构建立身份 → 文件整体交代出处 → 实际条款局部供阅读 | 全页小字无人能读；放大纸张却不指向口播所说条款 |
| 说明资源需求 | 按台词依次出现电表、冷却管道、设备等真实对象 → 用必要关系线连接 | 一张泛用机房照片持续缩放；凭空用箭头暗示未被证实的因果 |
| 比较两个对象 | 保留第一个对象的身份 → 移位引入第二个 → 突出对应差异 | 每次重新铺满同样的卡片；把“不同/并存”画成“A导致B” |

图表保留真实时间、坐标、比例和单位；原图等比展示，局部裁切另行明确焦点，不拉伸曲线制造涨跌感。指数跌幅、公司市值变化、资金支出不是同一口径。可以弱化无关区域，但不能删除影响结论的上下文。确实需要整体与局部并列时，建立清楚的主次与位置关联，避免两张同等权重的重复图。

文件先交代身份，再让实际关键句占据可读面积。截取段落保留必要限定；不得拼出来源中不存在的条款。数字随原声出现，不让动画提前泄露下一句结论。钱币只作价值或分配的视觉比喻，不能将估值、股份或计划剪成实际现金到账。

## 3. 构图随信息改变

- 大幅实景用于认识对象，局部用于看细节，分层对象用于解释关系，真人用于观点、反应和连接。避免全片只有“固定标题＋小窗＋图片”的一种构图。
- 用户要求全屏时，先让素材成为主画面。竖版实景可铺满；横向图表和文件先完整、等比、尽量大幅展示，再切可读细节。不为消灭黑边裁掉坐标、人物或关键内容，也不把横图挤在上半屏、下半屏长期空置。
- 黑色留白可以建立层次，但面积应由主体及阅读需求决定。通过重排对象、放大有效内容或补入确有必要的关系改善空置，不能用无关科技装饰填满。
- 当前任务已确认的配色、字体、真人背景、语速与字幕优先。已有纯黑底、白字、姜黄高亮的项目继续沿用；暖白/深色只是未确定风格时的起点。真实素材中的品牌色和自然色不必强行改成主题色。
- 查找长时间没有信息推进的段落，回到口播检查是否出现了新的具体对象或关系。该配的内容按语义补齐；表达情绪或关键态度时保留真人。覆盖率、最长真人段和状态间隔用于定位问题，不是统一配额，也不强制每两秒切镜。

已有成片的视觉修订先锁定已确认的剪口、速度、字幕时码和音轨；不因补素材擅自重剪论证。长段缺画面时优先补相应对象，不删掉价格、条件或其他必要说明来制造紧凑感。

## 4. 动画要检查运动中的构图

按语义安排“进入 → 变化 → 停稳/退出”，只有台词需要时才用视差、扇形展开或透视变化。动作参数见 [image-led-motion.md](image-led-motion.md)，不能用同一弹跳和缩放覆盖所有对象。

画面包含会移动或变大的纸张、照片、钱币时，在进入、中段、位移/缩放极值、最密集处和退出分别检查。重点排除：

- 白色文件移动到白字后方，导致标题、金额或单位消失；
- 新照片盖住还未读完的旧结论，旧标签残留成歧义；
- 关系线在对象移动后指错目标，比较被箭头误读为因果；
- 主体、画中画、字幕或来源在不同阶段互相遮挡。

优先调整对象路径、位置、尺寸和退出顺序，再决定是否需要紧凑底衬；不要给所有文字统一加厚框来掩盖构图问题。修正一个极值后复看相邻状态，避免只修静帧却引入新的运动遮挡。

## 5. 用同一句口播比较修改效果

保留上一版，比较同一语义段的旧版、修订版和对应参考方法。检查主体是否更容易辨认、证据是否更容易阅读、动作是否真的解释关系；不以“更满”“切得更多”或单帧更花哨作为进步标准。

在最终 MP4 中查看开头、中段、密集动作和结尾，并用约 360 px 宽预览验证手机阅读。连续播放代表动作；阅读停留触发低运动检测时，结合上下文与实际画中画判断，不能把所有提示一概忽略。音轨哈希一致只说明声音未变，不代表做过听感检查。完整技术检查仍按 [render-and-qa.md](render-and-qa.md)。

交付记录实际修正、查看范围和仍未验证的部分。只归档可复用方法，不将这期素材、时码、覆盖比例、渲染坐标或音轨固化为新项目默认值。
