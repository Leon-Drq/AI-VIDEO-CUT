# 前 3 秒与素材精修

用于本 skill 的开头强化、无网址成片和素材质感升级。沿用当前项目、已确认音轨及字幕时间轴；只有需要修改对白时才重新剪音频。下面的时间和尺寸是制作起点，不强制每条视频套同一种卡片动画。

## 前 3 秒：让观众马上知道看什么

按**最终成片时间**规划 0–3 秒，在分镜中写出核心看点、对应台词、素材对象和动作的意义。

| 时间起点 | 画面任务 | 可选手法 |
| --- | --- | --- |
| 0–0.5 秒 | 首帧就有可识别的对象或结果，听读能对应 | 真人与真实案例同屏，或先给结果局部；不以空背景、片头标志或长淡入占掉开场 |
| 0.5–1.5 秒 | 呈现一句核心看点，让素材解释它 | 两三层真实页面或实物依次展开、整体到关键细节；通常 0.3–0.6 秒减速落稳 |
| 1.5–3 秒 | 留出看懂的时间，接入第一段正文 | 从局部回到整体或从真人同屏转入大幅案例；保留同一对象形成衔接 |

- 信息胜过切镜数量。一张强相关照片配有意义的推近也能成立；情绪、表情是看点时保留真人，不强塞三张卡片。
- 素材优先于大字。开头最多突出一个核心短句；完整口播仍由字幕承接，不堆“震撼、逆天、必看”等无证据结论。
- 案例预览可以提前建立主题，在分镜注明原因；具体人物、数字、排名、参数、收益和“前后效果”仍跟随语义锚点。不同项目不能拼成同题优化前后对照。
- 已有成片仅要求视觉加强时，不重复加速、不改变剪口、不剪掉限定词。没有可靠配图时用真实对象细节或人物表达，不编造效果图当证据。
- 留出完整脸、发顶、嘴和关键手势；入场路径也不能穿过这些区域。过渡音效仅在确有听感收益时添加，不为“冲击力”强改已确认音轨或使用压过对白的重击。

## 画面内不出现网址

检查所有可见层：自制来源角标、浏览器地址栏、截图正文与页脚、录屏滚动内容、真人后方屏幕、字幕、结尾卡、下载提示、短链接及用来引流的二维码。`https://` 不是唯一形态，裸域名和省略协议的地址也要找。

推荐处理顺序：

1. 获取无浏览器外框的真实页面素材，或重新截图只取需要的内容；保留对象名称、证据、日期和必要上下文。
2. 在不影响事实含义的前提下裁去地址栏、导航页脚或边缘链接。整体案例和后续放大细节分别检查，裁过一次不代表所有运镜安全。
3. 对录屏中的固定地址区域做随画面运动的遮挡或重新取景；人物后方屏幕按实际画面范围处理，不能遮到人物。用于真实资料的编辑不得改写数字、排名或结果。
4. 来源角标只写确有必要的机构、作者、产品名称或采集日期。结束画面用相关案例、真人收束或内容主题，不加域名、短链接、二维码。
5. 将完整来源地址、作者、许可依据与裁切/遮挡说明保存到 `SOURCES.md` 或素材清单。清除画面网址不等于丢掉来源记录。

对象名称与网址区分处理：`GitHub`、产品名和命令中的仓库标识不是自动判定为网址；命令若含实际 URL，换用不展示 URL 的步骤说明或其他真实界面，把完整可执行命令另存文档，不删改命令后伪装成可运行结果。

保留需要的非网址署名和许可说明。某素材的许可确实要求画面内显示网址时，优先换成满足无网址要求的来源，不静默抹掉强制署名。无法替换且确为关键素材时才说明具体冲突，不因此为普通裁切建立审批流程。

## 暖白与深色：按内容组织

两个场景共享字体、强调色、边距和字幕样式，保持同一条片子的视觉连续性：

| 场景 | 起点 | 适合承载 |
| --- | --- | --- |
| 暖白 | 米白/浅暖灰背景，炭黑字，柔和中性阴影 | 网页设计、产品图片、版式和照片细节，保留素材本身的颜色 |
| 深色 | 炭黑/深蓝灰背景，米白字，一种克制强调色 | 工具图标、代码与流程、数据或证据；重点仍是素材本身 |

按段落语义和素材色彩组织明暗交替，不每隔固定秒数反转颜色，不为数量机械交替或闪白。只有一个视觉段落、或用户另有统一配色时可以只用一个场景，并说明构图选择。不要把整张照片压暗以适应深色模板。

这里的底色指**素材展示场景**。真人拍摄背景另行处理；用户要求真人背景补光时只调整身后的环境，保护肤色、头发和衣服，不把素材背景变亮当成真人补光完成。

## 案例细节、叠层与阴影

- 先展示足以辨认对象的整体，再放大一个能解释台词的真实局部：排版看字级和留白，动效看实际录屏或明确标注的页面分层演示，参数看原始控制区。不得把自制运镜说成产品本身会执行的动效。
- 检查源图像素和目标尺寸。局部放大后模糊、字被裁断或关键结构看不全，就换更清晰的原素材或降低放大量，不能靠锐化冒充细节。
- 通常以一张主案例配一两层次要细节开始。通过合理大小、轻微透视和前后遮挡建立主次；不是把同一截图复制成一排同样大的框。重复案例仅用于开场预览、正文解释或结尾呼应，并记录用途。
- 主体、说明文字、真人和字幕先排位置，再加动作。检查最密集阶段、局部弹出、退场及横竖版重排后的边界，不能只看停稳的漂亮帧。素材应让开小标题、数字单位和署名。
- 阴影使用统一的光向、轻微偏移和柔边；以实物与背景的距离决定深浅。避免粗黑光晕、各层不同光向、无故悬浮和整屏发光边框。倾斜与透视保持字和产品可辨认，不用大角度旋转制造廉价感。
- 横版重新利用横向空间：大幅案例搭真人侧栏、必要时图解同屏；竖版注意上下层级和字幕底区。按最终尺寸调整标题、正文与人物占比，不把竖版直接拉宽或只填两侧黑边。

## 从最终成片验收

| 检查项 | 实际检查方式 | 需要返工的情况 |
| --- | --- | --- |
| 前 3 秒 | 在 0、0.3、0.7、1.5、2.5、3 秒附近及实际动作边界抽帧；具备播放能力时播放这段 | 首帧无对象，素材与话题无关，连续快闪无法读懂，遮脸，具体结论提前出现 |
| 网址 | 搜索项目中的渲染文字，再查看实际成片中的每个截图/录屏镜头、来源角标和收尾；有 OCR 时辅助定位裸域名 | 角标删了但地址栏仍在；运镜露出页脚；末帧又出现链接；只用字符串扫描宣称全片无网址 |
| 案例质感 | 查看整体、局部最大放大、最密集叠层、明暗切换与退场；再看约 360 px 宽预览 | 图像失真、看不出对象、细节模糊、阴影糊成黑边、标题与案例相挤或说明被盖住 |

输出检查报告时记录覆盖的镜头、时间点、发现的问题和修正；静帧检查不能声称验证了连续动效，缺少播放或 OCR 能力时如实写明实际方式。普通完整解码、音画时间轴、响度与字幕检查仍执行 [render-and-qa.md](render-and-qa.md)。
